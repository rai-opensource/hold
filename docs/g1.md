# Retargeted trajectories for G1

We provide motion trajectories retargeted for the Unitree G1 robot, based on 80%-scale BVH animations.
The trajectories were generated with the kinematic motion retargeting algorithm used in the [ZEST](https://www.science.org/doi/10.1126/scirobotics.aec7695) and [HuMBLE](https://arxiv.org/abs/2610.10489) projects.

The retargeted trajectories are stored in HDF5 (H5) format. They can be loaded with standard HDF5 libraries such as [h5py](https://www.h5py.org/) and viewed in the browser with [myHDF5](https://myhdf5.hdfgroup.org/).

We also provide a simple [MuJoCo](https://mujoco.org/)-based visualizer that plays these trajectories on the G1 robot (see [G1 motion visualizer](#g1-motion-visualizer)).

In addition, we are developing a Blender plugin for visualizing, editing, and photorealistically rendering these trajectories. It has not been released yet.

## Data format

Each H5 file stores the trajectory under `robot_data/trajectory_data`:
- `time`: timestamps in seconds.
- `joints/{labels,pos,vel}`: positions and velocities of the 29 joints. The joint order is given by `joints/labels` and differs between files, so always map joints by name.
- `bodies/{labels,pos_w,quat_w,lin_vel_w,ang_vel_w}`: world-frame body poses and velocities, with `[w, x, y, z]` quaternions.

Note that the `base` body corresponds to the frame of the G1 `torso_link`, not the pelvis.

## G1 motion visualizer

### Getting started

![G1 visualizer preview](../imgs/g1-visualizer.gif)

The visualizer uses the 29-DoF [Unitree G1 model from MuJoCo Menagerie](https://github.com/google-deepmind/mujoco_menagerie/tree/main/unitree_g1), which is downloaded automatically on first use. Its Python environment is managed with [uv](https://docs.astral.sh/uv/). On the first run, uv installs the locked dependencies and, if needed, Python 3.12 (pinned in [visualizer/.python-version](../visualizer/.python-version)).

Run it from the repository root:
```bash
uv run --project visualizer visualizer/visualize_g1.py data/g1/locomotion/walk                      # play every motion in a directory
uv run --project visualizer visualizer/visualize_g1.py data/g1/locomotion/sprint/s0_sprint_001.h5   # play a single file
```

If you prefer not to use uv, install the dependencies listed in [visualizer/pyproject.toml](../visualizer/pyproject.toml) (`glfw`, `h5py`, `mujoco`, and `numpy`) with pip in a Python 3.12 environment. Then run `python visualizer/visualize_g1.py <path>`.

Playback follows the timestamps stored in each file, so it runs in real time by default. Use `--speed` to change the initial speed.

The panel on the right lists all loaded files, with the file that is currently playing highlighted. Click a file to play it, and scroll over the list to see more files. Click the **Files** header to hide the list, which leaves a small **Files** tab in the top-right corner. Click the tab to show the list again.

The slider at the bottom of the window shows the elapsed time and the motion duration. Drag it, or click anywhere on it, to go back and forth in the motion. You can also drag the scene with the left mouse button to rotate the camera and scroll over it to zoom. The following keys are available:

| Key | Action |
|-----|--------|
| `Space` | Pause/resume |
| `←` / `→` | Seek 1 second backward/forward |
| `N` / `P` | Next/previous motion |
| `↑` / `↓` | Faster/slower |
| `R` | Restart the current motion |
| `Esc` | Quit |

### Troubleshooting

**`h5py` fails to build with `pkg-config probably not installed`.** No prebuilt `h5py` wheel exists for your Python version, so pip or uv tried to build it from source. Switch to Python 3.12. With uv, delete `visualizer/.venv` and run again. With pip, create a new Python 3.12 environment.

If you run into any other problem, please [open an issue](https://github.com/rai-opensource/hold/issues).
